# เอกสารออกแบบ WorshipChord

## เป้าหมาย

ช่วยนักดนตรีทีมนมัสการจัดลำดับเพลงและเปิดดูคอร์ดทั้งเพลงบนมือถือหรือ iPad แนวตั้ง เพลงส่วนตัวแยกตามบัญชีบน MongoDB Atlas และแชร์เพลงร่วมกันในกลุ่มที่ได้รับเชิญ

## ขอบเขตระบบ

1. เก็บเพลงส่วนตัวและ setlist วันนี้ใน MongoDB โดยกรองทุกคำขอด้วย `ownerId` ของบัญชี
2. เพิ่มคอร์ดด้วยการพิมพ์หรือวางข้อความในรูปแบบที่ระบบรองรับ
3. รุ่นนี้ไม่ค้นหาหรือดึงข้อมูลจากบริการภายนอก และไม่อ่านข้อความจากรูป
4. แก้เนื้อคอร์ด, เปลี่ยนคีย์, ปรับขนาดตัวอักษร และดูหน้าอ่านแบบเต็ม
5. เปิดหน้าอ่านคอร์ดและเลื่อนเพลงในชุดเพลงได้โดยไม่เปิดเพลงประกอบ
6. สำรอง/นำเข้าข้อมูลเพลงส่วนตัวเป็น JSON; ใช้ IndexedDB เป็นแคชแยกฐานตาม user ID
7. สมัคร/เข้าสู่ระบบเพื่อสร้างกลุ่ม เก็บเพลงกลุ่มใน MongoDB Atlas และซิงก์การแก้ไข/ลำดับผ่าน WebSocket ขณะหน้าเว็บเปิด
8. สมาชิกกลุ่มทุกคนเชิญผู้ดูได้; เจ้าของและผู้แก้ไขเชิญผู้ดูหรือผู้แก้ไขได้ เก็บคำเชิญและการตอบรับไว้ในกล่องแจ้งเตือน
9. Owner/editor ลากเพลงจากคลังส่วนตัวลงกลุ่มได้ และเปลี่ยนคีย์แสดงผลของเพลงกลุ่มให้สมาชิกเห็นแบบเรียลไทม์
10. สมาชิกคัดลอกเพลงกลุ่มเข้าคลังส่วนตัวได้ สำเนาเป็นอิสระและไม่แก้ต้นฉบับในกลุ่ม
11. หน้าอ่านจัดเนื้อเพลงไว้ในคอลัมน์กว้างพอดีสายตา แล้วปรับ padding/ขนาดตัวอักษรตามจอคอม iPad และมือถือ
12. หน้าอ่านแสดงรายการเพลงชุดปัจจุบันขนาดเล็กด้านข้างบนจอใหญ่; มือถือเปิด/ปิดรายการได้ และระบุเพลงปัจจุบันกับเพลงถัดไป
13. API ป้องกันเพลงซ้ำในคลังส่วนตัว เพลงวันนี้ และแต่ละกลุ่ม โดยเทียบชื่อเพลงกับศิลปินหลังปรับช่องว่าง
14. เมื่อออฟไลน์ แสดงสำเนาแคชเพลงส่วนตัว/เพลงวันนี้และให้แก้ไขเพื่อซิงก์ภายหลัง; เพลงกลุ่มยังต้องออนไลน์
15. หน้าบัญชีมี flow ลืมรหัสผ่านด้วย recovery code แบบใช้ครั้งเดียว เพราะระบบไม่มีบริการอีเมลยืนยัน
16. เชิญเข้ากลุ่มค้นบัญชีด้วยชื่อแสดงหรือรหัส WorshipChord ที่ไม่ซ้ำ โดยผู้รับยังต้องยอมรับคำเชิญก่อนเข้ากลุ่ม

## แนวทาง UX/UI

- ใช้ปุ่มหลักหนึ่งปุ่มต่อพื้นที่งาน และใช้ข้อความบอกผลลัพธ์แทนไอคอนที่เดาความหมายยาก
- หน้ารายการเริ่มจาก “เพลงวันนี้” แล้วตามด้วยคลังเพลง; ปุ่มเพิ่ม/ค้นหาและสถานะบัญชีต้องไม่เบียดกันบนมือถือ
- หน้าอ่านคอร์ดให้เนื้อเพลงเด่น รายการเพลงอยู่ข้างคอร์ดบนจอใหญ่ และย่อเป็นปุ่มเปิดรายการบนมือถือ
- แบบฟอร์มแสดงคำอธิบายใกล้ช่องกรอก; ข้อผิดพลาดระบุวิธีแก้และไม่ล้างค่าที่ผู้ใช้พิมพ์
- เป้าหมายสัมผัสมีขนาดอย่างน้อย 40px, focus มองเห็นได้, และเคารพการตั้งค่าลด motion ของอุปกรณ์

## ADR-001: เว็บแอป PWA พร้อมข้อมูลบัญชีบนคลาวด์

**สถานะ:** เลือกใช้

**การตัดสินใจ:** ทำเป็น responsive PWA ที่ใช้ Node.js API และ MongoDB Atlas สำหรับบัญชี เพลงส่วนตัว เพลงวันนี้ และกลุ่ม. IndexedDB เก็บแคชเฉพาะผู้ใช้ที่เข้าสู่ระบบอยู่

**เหตุผล:** ข้อมูลส่วนตัวซิงก์ข้ามอุปกรณ์ได้โดยบัญชีอื่นอ่านไม่ได้ ข้อมูลกลุ่มใช้สิทธิ์สมาชิกแยกต่างหาก และแคชในเครื่องแยกตามบัญชีเพื่อไม่ให้ข้อมูลปะปน

**ผลตามมา:** การสมัครและการซิงก์ข้ามอุปกรณ์ต้องออนไลน์และต้องตั้งค่า Atlas; หาก API หยุดทำงาน แอปใช้สำเนาบัญชีล่าสุดที่ลงชื่อเข้าใช้บนอุปกรณ์นี้ได้ โดยไม่เปิดแคชของบัญชีอื่น. เมื่อ logout จะล้างตัวระบุบัญชีออฟไลน์และไม่เปิดแคชเดิมในหน้าที่ออกจากระบบ

## ADR-002: ใช้รูปแบบคอร์ดในเนื้อหาแบบ `[Chord]`

**สถานะ:** เลือกใช้

**การตัดสินใจ:** บันทึกข้อความตามต้นฉบับ รองรับทั้งวงเล็บคอร์ดในเนื้อ เช่น `[G]`, `[D/F#]` และแถวคอร์ดล้วน เช่น `G C` ระบบสร้างข้อความแสดงผลจากคีย์ต้นฉบับและคีย์ปลายทาง

**เหตุผล:** รักษาอักขระไทยและเนื้อเพลงให้ไม่เปลี่ยนจากการ transposition และแก้ข้อความคอร์ดได้โดยตรง

**ข้อจำกัด:** แถวคอร์ดล้วนต้องแยกจากเนื้อเพลงชัดเจน เพื่อไม่ให้ระบบไปเปลี่ยนตัวอักษรในเนื้อร้องเป็นคอร์ด

## ADR-003: ป้อนเนื้อเพลงและคอร์ดด้วยข้อความ

**สถานะ:** เลือกใช้ในรุ่นปัจจุบัน

**การตัดสินใจ:** ให้ผู้ใช้พิมพ์หรือวางเนื้อเพลงและคอร์ดลงในตัวแก้ไขโดยตรง โดยคงตัวอย่างรูปแบบ `[G]` และแถวคอร์ดล้วนไว้

**เหตุผล:** ลดการพึ่งบริการภายนอกและหลีกเลี่ยงการนำเข้าข้อความหรือคอร์ดที่จัดแนวผิดโดยอัตโนมัติ

## ADR-004: พักการอ่านคอร์ดจากรูป

**สถานะ:** พักไว้; ไม่มีในรุ่นปัจจุบัน

**การตัดสินใจ:** ปิดการอัปโหลดรูปและการประมวลผล OCR ออกจากเว็บ จนกว่าจะมีแนวทางที่รักษาความถูกต้องของคอร์ดและภาษาไทยได้

**ผลตามมา:** ผู้ใช้เพิ่มเนื้อเพลงและคอร์ดด้วยการพิมพ์หรือวางข้อความเอง

## ADR-005: แชร์ผ่าน MongoDB Atlas และ Node.js API

**สถานะ:** เลือกใช้

**การตัดสินใจ:** เก็บเพลงส่วนตัวและเพลงวันนี้ใน MongoDB โดยใช้ `ownerId` ผูกกับบัญชี; เก็บเพลงที่แชร์ใน `groupSongs` และกำหนดสิทธิ์ผ่านสมาชิกกลุ่ม. Node.js ให้บริการหน้าเว็บ, API, session cookie, การตรวจสิทธิ์ และ WebSocket สำหรับส่งเหตุการณ์การเปลี่ยนแปลง

**เหตุผล:** ข้อมูลบัญชีเดียวกันซิงก์ได้หลายอุปกรณ์ และ query สำหรับเพลงส่วนตัวบังคับ owner filter; การแชร์เกิดเฉพาะเมื่อเจ้าของเพิ่มเพลงเข้า collection กลุ่ม

**ผลตามมา:** การสมัคร การแชร์ และกลุ่มต้องเชื่อมต่ออินเทอร์เน็ตและใช้ Atlas credentials ผ่าน `.env` ฝั่ง server เท่านั้น; client ไม่เห็น connection string. เพลงกลุ่มไม่ปะปนกับเพลงส่วนตัวหรือ JSON backup. IndexedDB แยกฐานข้อมูลและคิวซิงก์ตาม user ID เพื่อไม่ให้ cache ข้ามบัญชี. รุ่นนี้ broadcast ด้วย WebSocket จาก process ของแอป จึงควรรัน Node.js instance เดียว หากจะ scale หลาย instance ต้องใช้ shared pub/sub หรือ consume MongoDB change streams

## ADR-006: คำเชิญและกล่องแจ้งเตือนแบบ persisted inbox

**สถานะ:** เลือกใช้

**การตัดสินใจ:** กล่องแจ้งเตือนเก็บใน MongoDB และแสดงย้อนหลังเมื่อผู้ใช้กลับมาเปิดเว็บ; WebSocket ใช้แจ้งเหตุการณ์ทันทีเมื่อผู้ใช้เปิดหน้าเว็บอยู่

**เหตุผล:** ไม่ต้องพึ่งบริการ push notification ภายนอกหรือระบบส่งอีเมล จึงไม่เพิ่มผู้ให้บริการอีกเจ้าในรุ่นนี้

**ผลตามมา:** เมื่อปิดเว็บจะไม่มีเสียง/แบนเนอร์จากระบบปฏิบัติการ ผู้รับที่ยังไม่มีบัญชีต้องสมัครด้วยอีเมลที่ถูกเชิญก่อนจึงจะเห็นคำเชิญ ระบบยังไม่ยืนยันว่าเจ้าของบัญชีควบคุมอีเมลนั้นจริง

## ADR-007: คีย์แสดงผลร่วมกันในเพลงกลุ่ม

**สถานะ:** เลือกใช้

**การตัดสินใจ:** เก็บ `GroupSong.key` เป็นคีย์ต้นฉบับและ `GroupSong.displayKey` เป็นคีย์ที่กำลังใช้ร่วมกัน Owner/editor เปลี่ยน `displayKey` ได้จากหน้าผู้อ่าน; API ตรวจสิทธิ์และ revision แล้วส่งเหตุการณ์ผ่าน WebSocket เพื่อให้สมาชิกคนอื่นโหลดเพลง/คอร์ดใหม่ Viewer เปลี่ยนคีย์เฉพาะมุมมองของตัวเองได้

**กติกา UX:** แสดงชื่อคีย์ตามผลกระทบที่ผู้ใช้กำลังจะทำ: Owner/Editor เห็น “คีย์เพลงในกลุ่ม” พร้อมข้อความว่าทุกคนจะเห็น; Viewer เห็น “คีย์ส่วนตัว” พร้อมข้อความว่ามีผลเฉพาะหน้าตน; เพลงส่วนตัวเห็น “คีย์แสดงผล”. ปุ่ม “คีย์ต้นฉบับ” มีคำอธิบายตามสิทธิ์ และไม่แก้ chord tokens

**เหตุผล:** ผู้เล่นเห็นคอร์ดคีย์เดียวกันระหว่างซ้อม/แสดง โดยไม่เขียนทับคีย์และ chord tokens ต้นฉบับ การเปลี่ยนคีย์ใช้กลไก transposition ตอนแสดงผลเดิม

**ผลตามมา:** การเปลี่ยนคีย์กลุ่มต้องออนไลน์; ถ้าสมาชิกกำลังแก้เพลงเก่าอยู่ revision conflict จะให้โหลดฉบับล่าสุดก่อนบันทึก

## ADR-008: คัดลอกเพลงกลุ่มเป็นเพลงส่วนตัว

**สถานะ:** เลือกใช้

**การตัดสินใจ:** สมาชิกกลุ่มทุกบทบาทคัดลอกเพลงที่มองเห็นไปยังคลังส่วนตัวได้ด้วยปุ่มหรือการลาก คัดลอกเนื้อเพลงที่ transposition แล้วตามคีย์แสดงผลปัจจุบัน และตั้งคีย์นั้นเป็นคีย์ต้นฉบับของสำเนา

**เหตุผล:** ผู้ใช้เก็บเพลงที่ต้องการไว้ในชุดของตนเองและแก้ไขได้ โดยไม่เปลี่ยนเพลงหรือ setlist ของกลุ่ม

**ผลตามมา:** แต่ละการคัดลอกสร้างเพลงส่วนตัวรายการใหม่; ถ้าชื่อและศิลปินซ้ำกับเพลงในคลังส่วนตัว API จะปฏิเสธและแจ้งให้ตรวจเพลงเดิม

## ADR-009: สิทธิ์เชิญสมาชิกตามบทบาท

**สถานะ:** เลือกใช้

**การตัดสินใจ:** สมาชิกทุกคนรวมถึง Viewer เชิญบัญชีเข้ากลุ่มได้ แต่สมาชิกทั่วไปเชิญได้เฉพาะ Viewer; Owner และ Editor เลือกเชิญ Viewer หรือ Editor ได้ API บังคับสิทธิ์นี้ทุกครั้ง

**เหตุผล:** ช่วยให้สมาชิกเพิ่มผู้ร่วมดูเพลงได้ โดยไม่เปิดทางให้ Viewer ยกระดับสิทธิ์แก้ไขกลุ่ม

**ผลตามมา:** ถ้าอีเมลยังไม่มีบัญชี WorshipChord ระบบแจ้งผู้เชิญและเก็บคำเชิญรอไว้ ระบบตรวจได้เฉพาะบัญชีใน WorshipChord ไม่สามารถยืนยันว่า Gmail นั้นมีอยู่จริงหรือส่งอีเมลยืนยันได้

## ADR-010: รายการเพลงในหน้าอ่าน

**สถานะ:** เลือกใช้

**การตัดสินใจ:** หน้าอ่านแสดงรายการเพลงขนาดเล็กไว้ด้านข้างคอร์ดบนจอใหญ่ และแสดงเพลงปัจจุบัน/เพลงถัดไป; บนโทรศัพท์ใช้ปุ่มเปิด/ปิดรายการเพื่อรักษาพื้นที่คอร์ด แตะชื่อเพลงเพื่อเปลี่ยนเพลงได้ รายการต้องตรงกับบริบทที่เปิดมา: เพลงวันนี้, คลังส่วนตัว หรือกลุ่ม

**เหตุผล:** นักดนตรีเห็นลำดับเพลงข้างคอร์ดบน iPad/คอมพิวเตอร์และเปิดรายการได้ทันทีบนมือถือ โดยไม่ต้องเลื่อนกลับไปหน้าคลัง

## ADR-011: ป้องกันเพลงซ้ำในแต่ละรายการ

**สถานะ:** เลือกใช้

**การตัดสินใจ:** ตรวจซ้ำที่ API โดยเทียบชื่อเพลงและศิลปินหลังปรับ Unicode เป็น NFC, ตัดช่องว่างหัวท้าย, ยุบช่องว่างซ้ำ และไม่แยกตัวพิมพ์ใหญ่/เล็ก ชื่อเดียวกันแต่คนละศิลปินถือเป็นคนละเพลง กติกานี้ใช้แยกกันในคลังส่วนตัวของแต่ละบัญชี, เพลงวันนี้ของแต่ละบัญชี, และเพลงในแต่ละกลุ่ม เมื่อซ้ำให้ปฏิเสธการเพิ่ม/แก้ไขและแจ้งผู้ใช้ให้ตรวจรายการเดิม

**เหตุผล:** การตรวจที่ API ครอบคลุมการเพิ่มจากปุ่ม, drag-and-drop, การนำเข้าไฟล์, และการแก้ไข โดยไม่ขึ้นกับการตรวจเฉพาะหน้าเว็บ; unique partial index กันคำขอพร้อมกันในคลังส่วนตัวและกลุ่มไม่ให้เพิ่มซ้ำ เพลงเดียวกันอยู่ในคลังส่วนตัวและเพลงวันนี้พร้อมกันได้ เพราะเป็นคนละรายการ; แต่เพลงวันนี้ห้ามมีเพลงซ้ำกันเอง

## ADR-012: แก้เพลงส่วนตัวแบบออฟไลน์และซิงก์ภายหลัง

**สถานะ:** เลือกใช้

**การตัดสินใจ:** เมื่อ `/api/me` หรือ API เพลงใช้ไม่ได้ ให้ใช้แคช IndexedDB ของบัญชีที่ลงชื่อเข้าใช้ล่าสุด แสดงสถานะออฟไลน์ อนุญาตเพิ่ม/แก้/ลบเพลงส่วนตัวและแก้ลำดับเพลงวันนี้ แล้วเก็บการเปลี่ยนแปลงเป็นคิวแยกตามบัญชีเพื่อส่งเมื่อเชื่อมต่อได้อีกครั้ง การแก้ไข/เชิญในกลุ่มต้องออนไลน์. เก็บตัวระบุบัญชีล่าสุดไว้โดยไม่มีข้อมูลรับรอง; การ logout ล้างตัวระบุนั้นเพื่อไม่ให้เปิดแคชหลังออกจากระบบ

## ADR-013: รีเซ็ตรหัสผ่านโดยไม่มีอีเมล

**สถานะ:** นำไปใช้แล้ว

**การตัดสินใจ:** ตอนสมัครสร้าง recovery code แบบสุ่มและแสดงให้ผู้ใช้บันทึกหรือดาวน์โหลดเพียงครั้งเดียว ผู้ใช้กด “ลืมรหัสผ่าน” แล้วกรอกอีเมลบัญชีกับ recovery code เพื่อกำหนดรหัสผ่านใหม่ ระบบเก็บเฉพาะ hash ของ recovery code และทำให้ใช้ซ้ำไม่ได้หลังรีเซ็ตสำเร็จ

**UX:** หน้าเข้าสู่ระบบมีลิงก์ “ลืมรหัสผ่าน?”; หน้าสมัครมีขั้นตอนยืนยันว่าบันทึก recovery code แล้ว และมีคำเตือนว่าหากทำหายจะไม่มีช่องทางกู้บัญชีทางอีเมล

**เหตุผล:** ระบบไม่มีการส่งอีเมลจริง จึงไม่ควรทำ flow ที่อ้างว่าส่งลิงก์ reset ไปยัง inbox

## ADR-014: ตัวตนและชื่อบัญชี

**สถานะ:** นำไปใช้แล้ว

**การตัดสินใจ:** อีเมลที่ normalize เป็นตัวพิมพ์เล็กยังต้อง unique สำหรับเข้าสู่ระบบและคำเชิญ ชื่อแสดงซ้ำได้เพื่อรองรับชื่อจริงซ้ำกัน ทุกบัญชีมี `publicId` แบบสุ่มและไม่ซ้ำ ใช้แชร์ให้คนอื่นค้นหา; ไม่เปิดเผยอีเมลในผลค้นหา

**UX:** หน้า “บัญชีของฉัน” แสดงชื่อแสดงและ public ID พร้อมปุ่มคัดลอก ID; คำแนะนำการเพิ่มเพื่อนให้แชร์ ID นี้เมื่อค้นด้วยชื่อแล้วเจอหลายบัญชี

## ADR-015: ค้นหาบัญชีเพื่อเชิญเข้ากลุ่ม

**สถานะ:** นำไปใช้แล้ว

**การตัดสินใจ:** ช่องเชิญเปลี่ยนเป็นค้นด้วย public ID หรือชื่อแสดง ค้นชื่อแบบไม่ตรงตัวได้และแสดงผลลัพธ์เฉพาะ `publicId` กับ `displayName`; หากชื่อซ้ำ ผู้เชิญต้องเลือกรายการโดยตรวจ ID ก่อนส่งคำเชิญ คำเชิญยังคงส่งถึงบัญชีที่เลือกและผู้รับต้องกดยอมรับก่อนเข้ากลุ่ม

**UX:** ผลค้นหาแสดงชื่อและ ID, เลือกผู้รับได้ทีละคน, ตั้งสิทธิ์ตามบทบาทผู้เชิญ และมีสถานะ “คำเชิญส่งแล้ว/รอรับ”; ถ้าค้นไม่พบแสดงวิธีแชร์ ID และทางเลือกให้ผู้รับสมัครบัญชีก่อน

**กติกาการชนกัน:** หากเพลงบนคลาวด์มี revision ใหม่กว่ารายการออฟไลน์ ให้หยุดซิงก์เพลงนั้นและถามว่าจะใช้ฉบับคลาวด์ ใช้ฉบับออฟไลน์ หรือเก็บทั้งคู่ ห้ามเขียนทับแบบเงียบ ๆ. หากลำดับคลังหรือเพลงวันนี้ชนกัน ให้เลือกใช้ฉบับคลาวด์หรือฉบับในเครื่องก่อนซิงก์ต่อ

**ข้อจำกัด:** หากอุปกรณ์ยังไม่เคยลงชื่อเข้าใช้และไม่มีแคชของบัญชี จะไม่มีสำเนาบัญชีให้แสดงขณะออฟไลน์; การออกจากระบบต้องไม่เปิดเผยแคชของบัญชีก่อนหน้า

## PRD-UI: การจัดเพลงกลุ่มและหน้าอ่านหลายขนาดจอ

- Owner/editor เพิ่มเพลงจากคลังส่วนตัวด้วย drag-and-drop ลงพื้นที่กลุ่มหรือด้วยปุ่มแชร์ที่แถวเพลง; ปุ่มแชร์เป็นทางเลือกสำหรับหน้าจอสัมผัส
- Owner/editor เรียงเพลงกลุ่มด้วย drag-and-drop หรือปุ่มลูกศรที่ใช้งานบนมือถือได้
- Owner/editor เปลี่ยนคีย์กลุ่มจากหน้าอ่านและสมาชิกที่เปิดเพลงเดียวกันเห็นการอัปเดตทันที; Viewer ปรับคีย์เฉพาะตัวได้โดยไม่เขียนกลับ
- ป้ายกำกับคีย์ต้องบอกขอบเขตผลลัพธ์: `คีย์เพลงในกลุ่ม`, `คีย์ส่วนตัว`, หรือ `คีย์แสดงผล` พร้อมข้อความกำกับสั้น ๆ ก่อนเปลี่ยน
- คงคีย์ต้นฉบับและภาษาไทยไว้; วางคอร์ดด้วย layout เดิมโดยไม่แก้ chord tokens
- หน้าอ่านใช้คอลัมน์เนื้อเพลงกว้างจำกัดเพื่อไม่ให้บรรทัดยาวเกินอ่าน และลด padding/ตัวอักษรตามพื้นที่จริงบน desktop, tablet และ phone
- Controls ต้อง wrap โดยไม่ซ้อนหรือล้น; พื้นที่สัมผัสมีขนาดเหมาะสมและมีปุ่มลำดับทางเลือกเมื่อ drag ไม่สะดวก

## PRD-UI: คลังกลุ่ม ชุดย้อนหลัง และการทำงานหลายรายการ

**สถานะ:** ข้อกำหนดและการออกแบบของงานวันที่ 26 พ.ย. 2026

- แยกคลังเพลงกลุ่มที่ใช้ซ้ำออกจากชุดเพลงตามวันเล่นอย่างชัดเจน สมาชิกกลุ่มทุกคนเปิดเพลงในคลังกลุ่มเพื่ออ่านเนื้อร้องและคอร์ดได้; owner/editor เท่านั้นที่แก้เพลง ลบออกจากคลัง หรือเปลี่ยนข้อมูลร่วมกันได้
- แสดงจำนวนเพลงทั้งหมดในคลังส่วนตัว โดยแยกจำนวนผลค้นหา/หน้าปัจจุบันออกจากจำนวนรวม
- หนึ่งสัปดาห์สร้างชุดได้ไม่จำกัด และวันเล่นซ้ำกันได้ ชุดแต่ละชุดมีชื่อแก้ไขได้ วันที่เล่น ลำดับเพลง และ snapshot ของเพลงเพื่อไม่ให้ชุดอื่นเปลี่ยนตาม
- แสดงจำนวนชุดย้อนหลังและเปิดรายการย้อนหลังเพื่ออ่านหรือคัดลอกมาใช้ใหม่ได้ ประวัติมีประโยชน์สำหรับดูชุดที่เคยเล่นและนำลำดับเดิมกลับมาใช้; ไม่กำหนดเพดานจำนวนชุดที่เก็บ
- เจ้าของและผู้แก้ไขย้ายชุดไปถังขยะและกู้คืนได้ ชุดในถังขยะถูกลบถาวรหลัง 30 วัน ห้ามย้ายชุดสุดท้ายที่ยังใช้งานอยู่ไปถังขยะ
- แสดงชุดที่ไม่ถูกลบทั้งหมดแบบแบ่งกลุ่มตามวันเล่น; ย่อรายการย้อนหลังไว้และมีจำนวนกำกับ เมื่อเปิดประวัติให้ค้นหาหรือเลื่อนดูชุดเก่าได้
- รองรับเลือกหลายเพลงเพื่อเพิ่ม/เอาออกจากเพลงวันนี้, ชุดกลุ่มที่เลือก, และคลังกลุ่ม; การลบเพลงออกจากคลังส่วนตัว/คลังกลุ่มเป็นคำสั่งแยกจากการเอาออกจาก setlist พร้อมกล่องยืนยัน
- การ bulk action ต้องบอกจำนวนที่เลือกและเป้าหมายก่อนยืนยัน ยกเลิกการเลือกเมื่อเปลี่ยนคลัง กลุ่ม หรือชุด เพื่อป้องกันลบ/เพิ่มผิดบริบท
- กดรีเฟรชแล้วกลับไปยังแท็บ กลุ่ม ชุด และเพลงที่กำลังอ่านก่อนหน้าได้ โดยไม่คืนฟอร์มแก้ไขที่ยังไม่ได้บันทึกหรือเปิดกล่องโต้ตอบซ้ำ

## ADR-016: หลายชุดต่อสัปดาห์และการเก็บชุดย้อนหลัง

**สถานะ:** ยอมรับและนำมาใช้

**บริบท:** ปัจจุบัน API ปฏิเสธชุดที่มีวันเริ่มสัปดาห์เดียวกัน ทำให้สร้างหลายชุดสำหรับสัปดาห์หรือวันเดียวกันไม่ได้ และไม่มีถังขยะสำหรับชุดที่ไม่ใช้แล้ว

**การตัดสินใจ:** `Group.weeklySets` เป็นชุดอิสระที่ระบุด้วย `id`; `serviceDate` เป็นวันที่ใช้เล่นและ `name` เป็นชื่อที่ผู้ใช้ตั้งได้ ไม่ใช้วันเริ่มสัปดาห์เป็น unique key ดังนั้นสร้างหลายชุดในวันเดียวกันได้ แต่ละชุดเก็บ `songIds` และ `songSnapshots` ของตัวเอง ชุดหนึ่งมีเพลงไม่เกิน 500 เพลงตามขีดจำกัด setlist ปัจจุบัน

ชุดย้อนหลังเก็บต่อโดยไม่มีเพดานจำนวน; แสดงจำนวนและค้นย้อนหลังได้ การย้ายไปถังขยะตั้ง `deletedAt`/`deletedBy` โดยไม่ลบข้อมูลจริง การกู้คืนล้างสถานะดังกล่าว owner/editor ทำได้ทั้งสองอย่าง และ API ต้องป้องกันไม่ให้กลุ่มเหลือศูนย์ชุดที่ใช้งานอยู่

`activeSetId` คงไว้เป็นชุดหลักที่เจ้าของกลุ่มกำหนด/ชุดที่สร้างล่าสุด ส่วนการเลือกอ่านชุดอื่นเป็นสถานะเฉพาะอุปกรณ์ ไม่เปลี่ยนชุดที่สมาชิกคนอื่นกำลังเปิด

**ผลตามมา:** API สร้าง/ย้ายเข้าถังขยะ/กู้คืนชุดไม่ลบข้อมูล snapshot การลบเพลงจากคลังกลุ่มไม่ลบสำเนาที่บันทึกในชุดเล่น

## ADR-017: การเลือกหลายเพลงและการคืนหน้าจอหลังรีเฟรช

**สถานะ:** ยอมรับและนำมาใช้

**การตัดสินใจ:** แต่ละรายการมี checkbox และ toolbar ตามบริบท การเอาเพลงออกจาก setlist จะไม่ลบเพลงต้นทาง; การลบจากคลังส่วนตัว/กลุ่มเป็นคนละคำสั่งและต้องยืนยันก่อนส่ง API เลือกหลายเพลงแล้วเพิ่ม/เอาออกได้ตามสิทธิ์ของผู้ใช้

เก็บสถานะหน้าจอชั่วคราวด้วย `sessionStorage`: แท็บหลัก, group ID, set ID, และบริบท/รหัสเพลงที่กำลังอ่าน เมื่อ reload ให้โหลดข้อมูลจาก API/แคชแล้วคืนหน้าจอเดิม ห้ามเก็บเนื้อหาฟอร์มแก้ไขที่ยังไม่บันทึกหรือสถานะกล่องโต้ตอบ

**ผลตามมา:** bulk API ตรวจสมาชิกและสิทธิ์ฝั่ง server; state จาก sessionStorage เป็นเพียงตัวชี้ตำแหน่ง ไม่ใช่แหล่งข้อมูลหรือหลักฐานสิทธิ์

### สิทธิ์ในกลุ่ม

- `owner`: เชิญสมาชิก เปลี่ยนสิทธิ์ จัดลำดับ และแก้/ลบเพลง
- `editor`: ดู เพิ่ม แก้ ลบ และจัดลำดับเพลงกลุ่ม
- `viewer`: เปิดดูเพลงและเปลี่ยนคีย์/ขนาดตัวอักษรบนหน้าของตัวเอง แต่บันทึกการเปลี่ยนแปลงกลับกลุ่มไม่ได้

คีย์เพลงส่วนตัวขณะอ่านเป็นค่าการแสดงผลเฉพาะหน้าจอ ไม่เขียนทับคีย์ต้นฉบับ. สำหรับเพลงกลุ่ม Owner/editor เปลี่ยน `displayKey` ร่วมกัน ส่วน Viewer เปลี่ยนเฉพาะมุมมอง. เพลงส่วนตัวค้นหา/แก้ไข/ลบ/จัดลำดับได้เฉพาะเมื่อ `ownerId` ตรงกับ session user; เพลงกลุ่มตรวจ membership และ role. การแก้เพลงทั้งสองแบบใช้ revision ป้องกันการเขียนทับการแก้จากอุปกรณ์อื่นโดยไม่แจ้ง

### ศัพท์

- **เพลง (Song):** รายการชื่อเพลงพร้อมคอร์ดและเนื้อร้อง
- **ชุดเพลง (Setlist):** ลำดับเพลงที่ผู้ใช้จัดเรียงในหน้ารายการ
- **คีย์ต้นฉบับ (Source key):** คีย์ที่คอร์ดในเนื้อหาบันทึกไว้
- **คีย์แสดงผล (Display key):** คีย์ที่เลือกให้ระบบคำนวณคอร์ดใหม่ขณะอ่าน
- **คิวซิงก์ออฟไลน์:** การเปลี่ยนแปลงเพลงส่วนตัว/เพลงวันนี้ที่เก็บในเครื่องและรอส่งขึ้นฐานข้อมูล
- **ข้อมูลชนกัน (Sync conflict):** เพลงบนคลาวด์เปลี่ยนหลังอุปกรณ์เริ่มแก้แบบออฟไลน์ จึงต้องให้ผู้ใช้เลือกรุ่นที่จะเก็บ
- **PWA:** เว็บแอปที่ติดตั้งเป็นไอคอนบนหน้าจอมือถือได้
- **กลุ่มเพลง (Group):** ชุดเพลงที่เก็บบน Atlas มีสมาชิกและสิทธิ์ร่วมกัน
- **คลังเพลงกลุ่ม (Group library):** เพลงต้นทางที่สมาชิกใช้ซ้ำได้; การแก้คลังไม่เขียนทับ snapshot ในชุดเล่น
- **ชุดเล่น (Weekly set):** ลำดับเพลงที่กลุ่มใช้ในวันเล่นหนึ่งวัน; วันเดียวกันมีหลายชุดได้
- **ชุดหลัก (Active set):** ชุดที่กลุ่มตั้งเป็นค่าเริ่มต้น; การเลือกชุดอ่านบนอุปกรณ์เป็นสถานะเฉพาะเครื่อง
- **ถังขยะชุดเพลง (Set trash):** ที่เก็บชุดที่ซ่อนไว้ชั่วคราวและ owner/editor กู้คืนได้
- **เจ้าของ / ผู้แก้ไข / ผู้ดู (Owner / Editor / Viewer):** ระดับสิทธิ์ของสมาชิกในกลุ่ม
- **กล่องแจ้งเตือน (Inbox):** ประวัติคำเชิญและการตอบรับที่เก็บไว้เพื่อเปิดดูภายหลัง
- **revision:** หมายเลขรุ่นของเพลงกลุ่มที่ใช้ตรวจว่ามีคนอื่นแก้ก่อนบันทึกหรือไม่
- **คีย์ร่วม (Shared display key):** คีย์ที่ Owner/editor เลือกให้เพลงกลุ่มแสดงแก่สมาชิกทุกคน โดยเก็บแยกจาก source key

## PRD-UI: สำรองและนำเข้าคลังเพลง

**สถานะ:** ออกแบบและนำไปใช้ในแอปแล้ว

- รวมการสำรอง/ย้ายเพลงไว้ในหน้าต่างเดียวชื่อ **จัดการไฟล์เพลง** แล้วแยกชัดเจนเป็น “ส่งออกไฟล์” กับ “นำเข้าไฟล์” ก่อนเลือกปลายทาง
- ปลายทางนำเข้ามีสามตัวเลือก: **คลังส่วนตัว**, **เพลงวันนี้**, และ **คลังเพลงกลุ่ม** พร้อมระบุชื่อกลุ่มที่เลือกและผลกระทบก่อนเริ่ม
- นำเข้า **คลังส่วนตัว** เพิ่มเฉพาะเพลงเข้าคลังของบัญชี ไม่เปลี่ยนเพลงวันนี้
- นำเข้า **เพลงวันนี้** นำเพลงเข้า/จับคู่กับเพลงในคลังส่วนตัวก่อน แล้วเพิ่มลำดับจากไฟล์เข้าเพลงวันนี้ เพราะเพลงวันนี้อ้างถึงเพลงส่วนตัว; บอกผลนี้ก่อนยืนยัน
- นำเข้า **คลังเพลงกลุ่ม** เพิ่มเพลงไว้ใช้ซ้ำในคลังกลุ่มเท่านั้น ไม่เพิ่มหรือเปลี่ยนชุดเพลงสัปดาห์ใดอัตโนมัติ สมาชิกเลือกเพิ่มจากคลังเข้าชุดที่ต้องการภายหลัง
- เฉพาะ `owner` และ `editor` นำเข้า/ลบเพลงในคลังกลุ่มได้; `viewer` เปิดอ่านและส่งออกเพลงที่ตนมีสิทธิ์ดูได้ แต่ไม่มีสิทธิ์เขียนกลับกลุ่ม
- ทุกไฟล์แสดงหน้าตรวจสอบก่อนนำเข้า: จำนวนเพลงในไฟล์, เพลงใหม่, เพลงซ้ำ, เพลงที่ใช้ไม่ได้ และปลายทาง; ให้ผู้ใช้ยืนยันก่อนเขียนข้อมูล
- ตรวจเพลงซ้ำด้วยชื่อและศิลปินหลัง normalize ช่องว่าง/Unicode; คงรายการเดิมไว้และข้ามรายการซ้ำโดยค่าเริ่มต้น ไม่เขียนทับคีย์หรือเนื้อหาที่กลุ่มตรวจแล้ว
- หลังนำเข้าแสดงสรุปเพิ่ม/จับคู่/ข้าม/ผิดพลาด และบอกตำแหน่งปลายทางอย่างชัดเจน
- ใช้ไฟล์ JSON UTF-8 เพื่อรักษาอักษรไทย; จำกัดขนาดและจำนวนเพลงให้ตรงกับข้อจำกัด API ปัจจุบัน และปฏิเสธรูปแบบไฟล์ที่ไม่รู้จัก

## ADR-018: อายุถังขยะและการนำเข้าข้อมูลเพลง

**สถานะ:** นำไปใช้แล้ว; ถังขยะ 30 วันและปลายทางนำเข้าตามการออกแบบ

**การตัดสินใจ:** เก็บชุดที่ย้ายเข้าถังขยะไว้ **30 วันนับจากเวลาที่ย้าย** แล้วลบถาวร ช่วงเวลาดังกล่าวแสดงเวลาที่เหลือ พร้อมกู้คืนได้เฉพาะสมาชิก owner/editor เมื่อครบกำหนดชุดและ snapshot ที่ฝังอยู่จะถูกลบถาวร ไม่มีการลบเพลงจากคลังหรือชุดอื่นที่ยังอ้างถึงเพลงนั้น

ไฟล์ส่งออกคลังส่วนตัวมีเพลงส่วนตัวและลำดับเพลงวันนี้เป็นข้อมูลคนละส่วน; ไฟล์ส่งออกคลังกลุ่มมีเฉพาะเพลงในคลังที่ผู้ส่งมีสิทธิ์อ่าน ไม่รวมบัญชีสมาชิก/คำเชิญ และไม่รวมชุดเพลงรายสัปดาห์โดยปริยาย การนำเข้าเลือกปลายทางก่อนดูตัวอย่าง แล้วคงการเขียนแยกตามขอบเขตส่วนตัว/กลุ่มและสิทธิ์ฝั่ง server

สำหรับการนำเข้าเพลงวันนี้ ระบบเพิ่มเพลงที่ยังไม่มีเข้าในคลังส่วนตัวแล้วผูกลำดับเข้าเพลงวันนี้ ส่วนการนำเข้าเข้าคลังกลุ่มไม่แตะชุดรายสัปดาห์ เพลงซ้ำใช้รายการเดิมและไม่เขียนทับ; การเพิ่มรายการซ้ำหรืออัปเดตข้อมูลเดิมต้องเป็นการแก้ไขที่ผู้ใช้เลือกแยกต่างหาก

**ผลตามมา:** ต้องมี metadata วันหมดอายุที่ระดับชุด, กระบวนการลบข้อมูลเก่าที่ปลอดภัยต่อเอกสาร Group ที่ฝังหลายชุด, file preview พร้อมตัวเลือกปลายทาง, bulk API ที่ตรวจ role ซ้ำบน server และสรุปผลรายรายการ การลบตามกำหนดไม่ควรใช้ MongoDB TTL index กับ `weeklySets.deletedAt` เพราะเอกสารชุดฝังอยู่ในเอกสารกลุ่ม และ TTL อาจลบทั้งกลุ่ม

### ศัพท์เพิ่มเติม

- **ไฟล์เพลง (Song file):** ไฟล์ JSON UTF-8 สำหรับย้ายเพลง โดยไม่ใช่หลักฐานสิทธิ์เข้าถึงกลุ่ม
- **ปลายทางนำเข้า (Import target):** คลังส่วนตัว, เพลงวันนี้ หรือคลังเพลงกลุ่มที่ผู้ใช้เลือก
- **เพลงซ้ำ (Import duplicate):** เพลงที่ชื่อและศิลปินตรงกันหลัง normalize; ข้ามและเก็บฉบับปลายทางเดิมไว้
- **วันหมดอายุถังขยะ (Trash expiry):** เวลาที่ครบ 30 วันหลังย้ายชุดเข้าถังขยะและระบบลบชุดถาวร
